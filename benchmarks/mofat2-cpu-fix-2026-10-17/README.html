CPU Q scoring correction against MOFAT 2.0

The corrected runtime passes 888/888 CPU/Metal comparisons and 444/444 Python 3.9 CPU comparisons. Fresh wheel/source installs on Python 3.9 and 3.14 each pass 334 tests with 53 optional skips.

This audit investigates and corrects the three CPU final-score disagreements reported in the original Mac audit. The original reference package, saved fixtures, comparison tolerances, and strict CPU search acceptance rule were preserved.

Cause and correction

Both implementations used the same shared initial ranks and initial-search QMC points. Arithmetic differences in Python’s native CPU scorer changed the treatment of near-tied candidates:

  1. Python computed scaled correlations through exp(log(K)-max(log(K))). MOFAT 2.0 uses K/max(K) for representable ordinary correlations, avoiding a log/exp round trip. Direct scaling alone corrected case 0069.
  2. Python summed squared solved entries through one accumulation chain. MOFAT/Armadillo uses two chains for these small vectors. Matching that summation order corrected 0066 and its structure-fallback duplicate 0427.
  3. The first full rerun revealed case 0118 (p=5,l=4,m=64,N=128,n_aug=4, seed=42, CPU, standard). Vendor Cholesky factors differed by 1–2 floating-point units. Fixed recursive Cholesky panels for matrices of at most 64 rows matched the reference on Python 3.14, but Python 3.9’s SciPy/OpenBLAS still diverged.
  4. macOS now uses system Accelerate consistently, independent of SciPy’s bundled BLAS. That also resolves 0118 on Python 3.9. Other platforms retain SciPy’s BLAS/LAPACK capsules with checked integer ABI signatures.

The recursive algorithm splits each panel in half, solves the lower block, updates the trailing symmetric block, and recurses. It follows the algorithm specified by LAPACK DPOTRF2. Larger matrices retain the backend’s existing factorization routine.

The implementation change is in src/softDOE/_native.hpp, in Linalg, CpuState::initialize, and CpuState::norm; setup.py links the built-in Accelerate framework on macOS. Normal alpha=1 correlations use direct scaling. Any subnormal/zero correlation triggers recomputation of the entire affected evaluation column in log space. General alpha retains log scaling. This preserves the existing underflow handling.

This is a correction of numerical evaluation order with a material effect on greedy search outcomes. It does not change the Q formula, replace the reference with Python output, add a tie epsilon, or relax final-score acceptance. Floating-point behavior may still vary across other BLAS libraries or platforms; the audit establishes the results of the recorded runs, not universal bitwise parity.

Independent precision check

An 80-digit mpmath evaluation of the mathematical kernel criterion on the recorded binary input coordinates finds equal scores at the first differing 0066 and 0069 decisions (within 8.5e-81 and exactly at working precision, respectively). In 0118, candidate minus incumbent log Q is about -8.48e-16; double-precision Python had reported +1.78e-15 and R reported zero. Run precision_check.py with mpmath installed to repeat this independent calculation. The recorded values support the diagnosis of rounding-sensitive search. They do not establish that the R greedy result is a global optimum or that the correction always increases final Q.
